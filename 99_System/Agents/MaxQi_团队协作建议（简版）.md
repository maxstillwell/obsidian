# MaxQi 团队协作建议（简版）

> 适用对象：团队内容研究成员、协作型 Codex、系统维护者  
> 说明：本文是 `[[99_System/Agents/MaxQi_系统交接与团队协作说明]]` 的简版补充，方便团队快速理解当前系统与下一步改进方向。

## 一、先用一句话理解现在这套系统

MaxQi 目前是一套“三层系统”：

1. `Obsidian`：内部研究、项目推进、知识沉淀、正式稿源头。
2. `maxqi.com`：对外网站、后台、Land Intelligence 展示端。
3. `Vercel + Supabase`：运行环境、内容存储与发布承接层。

最重要的一点：

> `Obsidian` 不是网站源码仓库，网站内容也不是通过 Obsidian GitHub 自动发布。

## 二、团队成员现在最适合做什么

当前阶段，团队成员最适合负责：

1. 在 Obsidian 完成区域研究、2DD、项目整理和可发布稿件初稿。
2. 通过 Git 同步到 `maxstillwell/obsidian`。
3. 按统一模板整理研究结论、证据、地图、风险和下一步。

当前阶段，不建议团队成员直接负责：

1. 修改网站源码仓库。
2. 修改 Supabase 数据。
3. 操作 Vercel 配置。
4. 共享或长期持有生产环境敏感密码。

## 三、当前系统最需要注意的地方

### 1. 内容入口还不够统一

目前网站同时存在：

- `/writing`
- `/insights`
- `/projects`

这些内容类型边界还没有完全统一，团队在准备稿件前应先确认：

- 这是一篇长期观点文章？
- 一篇正式区域研究？
- 一个项目展示？
- 还是仅供内部使用的 2DD 资料？

### 2. `00_Research` 不应直接视为前端内容

`00_Research` 更适合放：

- 原始研究
- 底稿
- 证据整理
- 尚未收口的分析

如果内容准备对外使用，建议转成：

- `20_Knowledge`：长期方法论、观点、公开文章
- `30_Reports`：整理后的正式研究或发布版
- `10_Projects`：正式项目主档

### 3. “可同步到网站”必须人工确认

即使系统有白名单和路径过滤，也不能把 `website_sync: true` 当作批量操作。

每一篇准备进入网站的内容，都应人工确认：

- 是否包含敏感财务信息
- 是否包含内部会议内容
- 是否包含未核实判断
- 是否适合对外公开

## 四、建议团队先采用的工作分层

建议统一采用下面这套简单分层：

```text
00_Research = 原始研究 / 2DD 底稿 / 资料收集
10_Projects = 已进入正式推进的项目工作区
20_Knowledge = 长期认知、方法论、投资原则、公开文章
30_Reports = 可分享、可归档、可转前端的正式整理版
99_System = 模板、规则、协作说明、系统文档
```

## 五、接下来最值得改进的五件事

### 1. 统一内容类型

建议尽快明确以下四类内容的边界：

1. 内部研究
2. 区域 / 2DD 正式研究
3. 项目展示
4. 公开观点文章

### 2. 给 2DD 建标准模板

每一份找地或区域研究，至少应固定这些字段：

- 区域 / 地址 / LGA
- 面积
- 当前 zoning / overlay
- 当前用途
- 投资逻辑
- 5-10 年催化剂
- 风险与否决条件
- 关键证据来源
- 地图 / 坐标
- 研究日期
- 研究负责人
- 是否允许进入前端

### 3. 拆分权限

建议后续把：

- 网站后台密码
- Obsidian 同步密钥

拆成两套独立权限，避免多人共享同一个高权限入口。

### 4. 更新旧文档

团队后续协作前，建议优先更新：

- 网站 `README`
- 架构说明
- Obsidian 发布说明

否则新成员容易根据旧文档形成错误理解。

### 5. 建立“定期找地”系统

这是当前最值得投入的新工作。

目标不是一次性找几个地块，而是建立一个每周稳定运行的找地流程，重点覆盖：

- Realestate
- Domain
- Real Commercial

重点筛选：

- Victoria 为主
- 100 ha 以上
- 300 ha 以上优先
- 数量不求多，但要求稳定、可跟踪、可复盘

## 六、下一阶段建议重点

我建议团队下一阶段把重点放在：

1. 先把“找地流程”标准化。
2. 再把“研究模板”标准化。
3. 最后再决定哪些内容值得同步到网站。

原因很简单：

> 现在最重要的不是先扩网站，而是先让“发现地块 -> 初筛 -> 研究 -> 决定是否推进”这条主流程稳定下来。

## 七、建议讨论的问题

团队成员看完后，可以重点讨论下面几个问题：

1. 现在的内容分类是否足够清楚？
2. `00_Research`、`10_Projects`、`30_Reports` 的边界是否需要再明确？
3. 2DD 模板应该固定哪些字段？
4. 找地流程是一周一次人工执行，还是要逐步半自动化？
5. 哪些资料永远不应进入网站同步流程？
